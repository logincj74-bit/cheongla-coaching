# Personal content owner — v2.0.16

The existing server-bound season owner identifies the personal content owner by profile ID, approved/active state and its existing role requirement. No display-name or broad administrator flag grants this capability. Client capability is fetched from an authenticated RPC and cleared on account reset.

Personal owner: home copy/official channels, academy introduction, director notices and writing, MBTI documents and operations, daily messages, home videos/D-day, winter promotion cards, and dictionary/English answer content. Existing staff desk notices, information resources, SMS, schedules, meal/exam/fee work, account recovery, journals, study plans and consultation workflows remain under their existing operational helpers. Existing other-principal coaching helpers are unchanged. Shared resources retain owner-or-manager authoring.

- New home editor covers three blocks with multiline fields and contact links; owner-only save, optimistic conflict detection, archive, restore, two-phase purge and guarded empty-trash. Public text is rendered without HTML injection; tel/SMS/HTTPS links and asset logo paths are validated. Contact copies on other pages use the current home contact links.
- Only three public-copy rows were added to the existing versioned introduction store. Fingerprints of all existing rows in eight content tables match the pre-change values; no user content was deleted. No journals, study plans or consultation records were rewritten.
- Content-specific RPC guards/RLS/storage policies changed. Shared is_principal, can_manage_life and operational submission functions were not rewritten. Director-notice attachment functions already enforce the channel helper; recycled notices now respect their original channel.
- Passed isolated fake-account SQL tests including a same-name director and broad admin flag, private owner-registry denial, owner revision conflict/archive/restore, non-owner storage/dictionary/promotion write denial, staff desk/shared resources and operational helpers. Passed home-copy DOM editing/conflict/XSS/link/trash/empty/logout tests, personal-owner role/menu gates, current role-coaching DOM workflow, introduction editor, dictionary owner controls, home video/swipe, pinned SDK and bottom navigation.
- Historical role-desk/role-workflow fixtures lack current dependency stubs, and the older dictionary corpus fixture failed to resolve a base shard; those legacy checks were not used as evidence for this release. Current permission-focused and role-coaching checks passed.
- No production accounts were impersonated and no production test posts were submitted. Physical iPhone/iPad login/touch remains untested.
